# ADR-0014: Mobile-money payments through PVit: the callback is a hint, PVit's status API is the truth

**Status:** Accepted · **Date:** 2026-10-02

**Context.** Drivers pay their rent from the app with Airtel Money or Moov Money. PVit is the aggregator. Its payment callback is not signed, it can be replayed, and a payment can finish without any callback arriving. A forged or lost callback must never credit a driver wrongly or leave money unrecorded.

**Decision.**
- **A payment attempt is a row** (`payment_intents`, V21): PENDING, then SUCCESS, FAILED or EXPIRED. It carries our own `reference` (sent to PVit), PVit's transaction id, the amount, the fee and the driver's country. At most one attempt per driver can be PENDING (partial unique index); a stale one (older than `app.pvit.expire-after`) is closed first.
- **The amount comes from the server**: the driver's current arrears (whole units, penalties included), never from the request. In sandbox (`PVIT_SANDBOX_AMOUNT` set) a fixed test amount is collected instead, because PVit only succeeds below 1000 XAF; the ledger then records what PVit confirmed.
- **Starting** (`POST /api/v1/driver/payments {operator, phoneNumber}`): validate the operator for the country and the number (converted to the national format PVit expects, `074111111`), create the attempt, call PVit (outside any database transaction), store PVit's reference. A PVit failure closes the attempt and answers 502 `PAYMENT_PROVIDER_UNAVAILABLE`.
- **The callback** (`POST /api/callback`, public, `callback_url_code` registered at PVit) only says which attempt to look at. The service finds the attempt by our reference, then **asks PVit's status API with our reference** (verified against the sandbox: it answers 404 `TRANSACTION_NOT_FOUND` when given PVit's own transaction id) and acts on that answer: SUCCESS records the payment, FAILED closes the attempt, anything else changes nothing. It checks that PVit's answer carries the same reference. It always replies 200 with the echoed `transactionId` and `code` PVit requires, including for unknown references (so PVit does not retry forever and nothing leaks).
- **Recording money** reuses `PaymentService.record` (method AIRTEL_MONEY or MOOV_MONEY, reference = PVit's id, request id = the attempt id, so it is idempotent) in the same transaction as the attempt's closing, under a row lock: callbacks arriving together or replayed record it once. If PVit confirms but the payment cannot be recorded (for example the contract ended), the attempt stays PENDING, an error is logged, and the recheck retries.
- **The fee** (the driver pays it on top, `owner_charge=CUSTOMER`) is recorded as its own ledger line of type `FEE` (V21 allows it): it never counts toward the rent and is not reversed with the payment.
- **The safety net**: a job every minute checks attempts still pending after `app.pvit.recheck-after` (3 minutes) with PVit, in whichever country they belong to; an attempt still pending after `expire-after` (30 minutes) is closed as EXPIRED, but only when PVit answers that it has no such transaction (an outage never expires a payment). Expired attempts keep being checked for 6 hours, and a late SUCCESS is still recorded.
- **Tenant context.** The callback and the job know no country; the attempt is found by a cross-country native query (like the driver sign-in lookup in ADR-0013) and everything after runs in its country.
- **PVit client** (`infrastructure/pvit`): API version 2; the secret key (valid one hour) is kept in memory, renewed five minutes early and once more if PVit rejects it, and never logged. Settings come from `app.pvit.*` (the `PVIT_*` variables); the settings object hides its secrets from `toString`.
- **Quote** (`GET /api/v1/driver/payments/quote`): the amount, PVit's fee and, when a number is given, the account holder's name (PVit's KYC), shown in the app's Récapitulatif before paying.

- **The receipt.** A confirmed payment has a PDF receipt drawn on the server (OpenPDF, same branding as the contract: logo, company legal details of the driver's country, payer and contract, operator, number, transaction and reference, amount, fee and total, date and time in the country's timezone). It is served only to the payment's own driver (`GET /api/v1/driver/payments/{id}/receipt`), never cached, and can be shared from the app through the phone's share sheet (messaging, e-mail, save, print). The fee is shown rounded up to a whole FCFA, the same as in the app; the ledger keeps PVit's exact figure.

**Deferred.** IP filtering of PVit's addresses (to be done at the proxy in production; the status read-back already makes a forged callback harmless), refunds (`GIVE_CHANGE`) for the caution, and PVit's account balance and reports.

**Consequences.** (+) Money is only recorded from PVit's own answer, once, whatever order or number of callbacks arrive; a lost callback heals itself. (-) Every callback costs one extra PVit call; the sandbox's fixed amount means test payments do not match the real arrears.

**Amendment (2026-11-04): one operation account per operator.** Airtel Money and Moov Money are paid into separate PVit operation accounts (`PVIT_AIRTEL_OPERATION_ACCOUNT_CODE`, `PVIT_MOOV_OPERATION_ACCOUNT_CODE`). The account is chosen by the attempt's operator for starting a payment, reading its status and quoting fees; PVit's secret key is renewed and kept per account. The password, the URL codes and the callback code are shared. Production refuses to start unless both codes are set.
