# ADR-0013: Driver API: its own token audience, filter and permissions, and a cross-country sign-in lookup

**Status:** Accepted · **Date:** 2026-10-02

**Context.** [ADR-0008](0008-driver-accounts-separate-from-staff.md) decided that drivers are not staff and use phone or email plus password. The driver app now needs real endpoints. Two problems follow: a driver token must never open a staff door (and the reverse), and a driver signs in before any country is known while all driver data is `@TenantId`-scoped.

**Decision.**
- **Separate token.** Driver access tokens are JWTs with audience `driver`, subject = driver id and a `cid` (country id) claim. The staff parser rejects any token carrying the `driver` audience; the driver parser requires it. Same signing key and issuer, one `JwtService`.
- **Separate filter and path.** Everything under `/api/v1/driver/` is authenticated only by `DriverJwtAuthenticationFilter`; `JwtAuthenticationFilter` skips that path. `/api/v1/driver/auth/login` and `/auth/refresh` are public; the rest needs a driver token. The driver is reloaded from the database on every request, so a driver blocked or deactivated after the token was issued is refused at once.
- **Permissions from status, not roles.** The filter derives authorities each request: `driver:session` (logout, change password) always; `driver:self` (profile, account) and `driver:pay` (operators, later payments) unless the password must still be changed; `driver:contract` (vehicle) only for an ACTIVE driver. A first login (`must_change_password`) can therefore only change the password; a SUSPENDED driver can see the account and pay but not the contract (ADR-0008). BLOCKED and INACTIVE drivers get no authentication.
- **Tenant context.** `TenantContextFilter` sets the country from the driver principal; the driver id always comes from the token, never from the request, so a driver can only ever read their own data.
- **Sign-in lookup (the one tenant bypass).** Before authentication no country is known, so two native queries in `DriverRepository` (`findLoginCandidatesByEmail`, `findLoginCandidatesByPhone`) look across countries and return only id and country id. Phones match on their end, so a local number finds the stored international one; an ambiguous number (two matches) matches nobody and the driver must type the full international number. Everything after the lookup runs in the found country.
- **Sessions.** The access token lives like the staff one. The refresh token is the existing opaque Redis token, returned in the JSON body (a mobile client has no cookie), with subject `driver:<countryId>:<driverId>`; a refresh token with any other subject is refused. Refresh rotates; logout revokes; a password change revokes all of the driver's refresh tokens.
- **Throttling.** Failures are counted per driver (`failed_login_attempts`, `login_locked_until`, V19) with the same `app.brute-force` settings as staff; unknown and wrong credentials answer identically and cost the same time (a dummy hash is checked).
- **Operators.** The mobile-money operators a country offers live in `payment_operators` (V19, seeded for Gabon), read through `PaymentOperatorService`, never hardcoded in the app.

- **Profile, contract, documents and support.** The driver sees their own profile (with birth date and address), their active contract, which documents exist (the files themselves are not served yet) and their country's support channels, and their own profile picture (`GET /me/photo`, authenticated because driver files are private). A message to support is stored (`support_messages`, V20), limited to 5 per hour per driver, and raises a `DRIVER_MESSAGE` notification for the staff who hold `drivers:update` in that country; a staff inbox is a later screen.

- **The lock.** From `app.driver-app.lock-after-unpaid-days` unpaid rent days (default 3, `DRIVER_LOCK_AFTER_UNPAID_DAYS`) a driver is limited to the payment screen until every unpaid day is paid. The number of unpaid days is kept on the driver (`drivers.unpaid_days`, V22), updated by every payment and by the arrears job; the driver filter then withholds `driver:contract` (the vehicle and the contract), and `GET /account` answers `locked`. A payment always collects the whole arrears, never part of them, so one payment unlocks. `suspended` is reported separately: the automatic suspension at 72 hours stays until an administrator lifts it, even after everything is paid. The app follows these two flags: it opens on the payment screen, hides the tabs, and only lets the driver sign out.

**Deferred.** Per-IP throttling, audit rows for driver sign-ins (the audit service records a staff actor), document download endpoints, a staff inbox for support messages, and the payment endpoint (needs the PVit integration).

**Consequences.** (+) Strong separation proven by tests in both directions; no staff code paths touched except one skip rule. (-) A driver is read from the database on every request; the cross-country lookup is a deliberate, narrow exception to the tenant filter.
